# BoundEvo v0.5.0

BoundEvo v0.5.0 introduces a read-only Run Registry and aligned cross-run
comparison for the experiment bundles introduced in v0.4.

## Highlights

- Inspect existing run bundles using `boundevo runs`.
- Display complete, incomplete, and invalid run directories.
- Export run registry results as JSON.
- Compare two or more runs using `boundevo compare`.
- Align benchmark results using identical CEC2017 function, dimension, and
  method keys.
- Reject different benchmark coverage unless `--allow-partial` is explicit.
- Report criterion-specific leaders for mean objective error, runtime, and
  function-evaluation count.
- Compute the nondominated front across the three minimized objectives.
- Export comparisons to Markdown with `--output`.
- Flag different budgets, revision identifiers, platforms, seeds, repetition
  counts, and incomplete case coverage.
- Exercise run registry and comparison via automated tests and CI.

## Install

```bash
git clone https://github.com/ZJY-HSBL/BoundEvo.git
cd BoundEvo
pip install -e ".[cec2017,analysis,plot]"
```

## Commands

```bash
boundevo runs --root results/runs
boundevo runs --root results/runs --json

boundevo compare --root results/runs

boundevo compare \
  --root results/runs \
  --run-id experiment-001 \
  --run-id experiment-002 \
  --output results/comparison.md
```

## Interpretation

Cross-run comparisons use only aligned per-function/per-method cases. Mean raw
error can be dominated by high-scale benchmark functions. Different evaluation
budgets, hardware, code revisions, or random seeds can confound apparent gains.
The three-objective Pareto front expresses trade-offs, not an overall winner
or statistical significance. See [Run Registry](../../docs/run_registry.md).
